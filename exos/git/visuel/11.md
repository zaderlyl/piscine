## Cours
Une pull request demande de fusionner une branche dans une autre. Elle se relit avant d'être fusionnée, ici sur `origin`. Une fois fusionnée, ton `main` local se met à jour avec `git pull`.

```
Avant :   origin : main = A, et menu = A ← B      (pull request menu → main)
Après :   origin : main = A ← B                   (fusion faite sur origin)
          ton main : A, il suit après git pull
```

## Énoncé
Propose `menu` à `main` sur `origin` : ouvre la pull request, relis-la, approuve-la, puis fusionne-la. Mets ensuite ton `main` local à jour.

## Étapes
- pr ouverte | Ouvre la pull request de `menu` vers `main` : `gh pr create`. | `menu` est déjà publiée sur origin : c'est pour ça qu'on peut l'ouvrir.
- pr approuvee | Relis-la et approuve-la : `gh pr review --approve`. | Une pull request ne se fusionne pas sans relecture.
- pr fusionnee | Fusionne-la sur origin : `gh pr merge`. | La fusion se fait sur origin, pas dans ton dépôt local.
- serveur main | Repasse sur `main`, puis mets-le à jour : `git switch main`, `git pull`. | Ton `main` local suit maintenant origin.

## Indice
Le `git pull` se fait depuis `main`, pas depuis `menu`.

## Départ
```bash
git add index.html
git commit -m "Ajoute la page"
git remote add origin https://exemple.test/piscine.git
git push -u origin main
git switch -c menu
git add style.css
git commit -m "Ajoute le menu"
git push -u origin menu
```

## Solution
```bash
gh pr create
gh pr review --approve
gh pr merge
git switch main
git pull
```
